# 見た目の決まり

## トークン

- トークンファイル：`docs/tokens.css`（仮置き。本番の置き場所は立ち上げの S4 で決める）
- コードでもプロトタイプでも、トークンにない値（`p-[13px]`、`#3366ff` など）を使わない
- 色は、ライトとダークの両方の値をトークンに持たせる。最初は OS の設定に従い、ヘッダーのボタンで切り替えたら、その選択をその端末のブラウザに覚えておく
  - 理由：朝の暗い部屋でもスマホで読むため

## 雰囲気

紙と墨のような、温かみのある落ち着いた色。記事の見出しだけを明朝にし、ほかは角ゴシックのふつうのアプリの作りにする。飾りは少なくし、毎朝30件ほどを手早く読み流せるようにする。

## 色の使い分け

| トークン | 使う場面 |
| --- | --- |
| bg | ページの地 |
| surface | ヘッダー、記事のカード、カレンダーやダイアログなどの浮いた面 |
| ink | 見出しと本文。選んでいるカテゴリのタブの下線。選んでいる優先度の地。下に出る通知の地 |
| muted | 英語タイトル、件数、アイコンのボタンなどの補足。既読の記事の文字 |
| line | 枠線と区切り線。関連度・重要度・反響の目盛りのうち、足りない分。読み込み中の灰色の枠。押せない日付 |
| scrim | ダイアログや開いた絞り込みの後ろを暗くする幕。ライトでもダークでも暗くする |
| source-hn | Hacker News の印の丸。ソースを足すときは、ソースごとにトークンを足す |
| accent | 目立たせたいものだけ：保存した印、保存済みの件数の印、関連度・重要度・反響の5、主な操作のボタン（追加、作成、削除、再読み込み）、入力のエラー |
| on-accent | accent の上の文字 |
| link | 藍。記事のカテゴリ名、元記事へのリンク（記事を開く、HN で開く）、見出しに指を乗せたとき、「続きを表示」、カレンダーの今日と「最新へ」、カテゴリのリストで選んでいる行のチェック |
| notice-bg / notice-ink | 一覧の上に出すお知らせ（AI を使えなかった日など） |

- 関連度・重要度・反響は、5を accent、4以下を muted にする
  - 理由：値の高いものだけが目に入るようにするため
- 色は accent（赤）と link（藍）の2色だけにし、これ以上足さない。赤は目立たせたいものと押すボタンだけに使い、分類とリンクは藍にする
  - 理由：赤1色でカテゴリ名・リンク・高い値・ボタンを兼ねると、カード1枚に意味の違う赤が並び、どこを見ればよいか分からなくなるため。藍は紙と墨の地になじみ、色が増えてもにぎやかにならない

## 余白と並べ方

- 対応する画面の幅：スマホを基本にし、PC でも読める。PC では中身の幅を広げる
  - 理由：主に朝スマホで読むため
- ヘッダーは高さを抑えた1行。左にアプリ名、右に日付の切り替え。その右は、ログインしていないときは明暗の切り替えとログイン、ログインしているときは保存済みとアカウントのメニュー（キーワード設定、明暗の切り替え、ログアウトを入れる）
  - 理由：スマホの幅で、ヘッダーのボタンを4つまでに収めるため
- 絞り込みのマス目はページの上に置き、スクロールしてマス目が見えなくなったら、画面の上に帯を出す
  - 帯には、左に選んでいるものの札（選んでいるマスと同じ ink の地に、名前と件数）、その横に日付、右に枠付きの「絞り込み」ボタンを置く
  - 「絞り込み」を押すと、帯の下に同じ並びのマス目を開き、その下の記事を scrim で暗くする。ボタンは「閉じる」に変わり、暗い所を押しても閉じる
  - 理由：下まで読んだあとでも、すぐに絞り込みを変えられるようにするため。3段のマス目をずっと上に残すと、記事を読む場所が狭くなるため
- 記事は、角の丸いカードを縦に並べる。上から、ソースと印のボタン、カテゴリと一致したキーワード、見出し、英語タイトルとドメイン、要約、区切り線の下に指標と元記事へのリンク。左に列を作らない
  - 理由：スマホの狭い幅で、見出しと要約に幅を使うため
- 押せるもの（アイコンのボタン、小さな文字のリンク）は、見た目が小さくても、押せる範囲を広げる
- 一覧は、キーワードに関連する記事のあとに、見出し「キーワード外の話題」を置いて、キーワード外の記事を続ける
  - 理由：キーワードで選んだ記事と、視野を広げるための記事を見分けられるようにするため
- 設定の画面（キーワード）は、PC でも幅を広げすぎない

## 文字

- アプリ名は、題字用の書体（`font-brand`。Fraunces の角を丸くした太字）にする。ほかでは使わない
  - 理由：アプリの顔として印象に残し、紙と墨の温かさに合わせるため
- 記事の見出しは明朝（`font-serif`）にする。案内、操作は角ゴシック（`font-sans`）
- 大きさは3段階：記事の見出し、要約（本文）、補足（英語タイトル、カテゴリ、キーワード、指標、件数など）

## アイコン

- Google の Material Symbols（Outlined、太さ400）を、SVG で使う。矢印などの文字の記号は使わない
- 付いている・いないで切り替えるもの（保存、既読）は、付いているときに塗りつぶしの版にする

## 部品の使い分け

- 日付：ヘッダーの「‹ ｜ 日付 ｜ ›」の、つながったボタン。真ん中を押すとカレンダーが開き、選べる日（直近90日）だけを押せるようにする。それ以上進めない向きのボタンは、薄くして押せなくする
- 絞り込み：「すべて」、カテゴリ10個、「キーワード外」の12個を、同じ形の等幅のマス目に並べる（スマホは4列×3段、PC は6列×2段）。名前と件数を1行に並べた低いマスにし（縦に場所を取らないため）、選んでいるマスは ink で塗る。名前は6文字まで、件数は30件ほどなので、スマホの4列でも名前を切らずに収まる。記事が0件のカテゴリも薄い件数で同じマスに出し、横にはスクロールさせない
  - 理由：同じものがいつも画面の同じ位置にあると、場所で覚えて押せるため。文字数や件数で形を変えない。12マスなら、4列でも6列でも空きが出ない。赤（accent）は記事の中で使うので、絞り込みの操作は墨の色にする
- ソース：カードのいちばん上に、ソースごとの色の丸とソースの名前（「Hacker News」）を出す。元の記事のサイトは、英語タイトルの横にドメインで出す
- 投稿の種類（Show HN、Ask HN）：ソースの名前の横に、枠線だけの小さな札で出す
- 記事のカテゴリと一致したキーワード：見出しの上に、カテゴリ名を link の太字で出し、その横に一致したキーワードを地の色の小さな札で並べる
- キーワード外の記事：カテゴリ名の代わりに、方位磁針（explore）のアイコンと「キーワード外」を、ink の枠線の丸い札で出す
  - 理由：一覧の2割は選び方が違う記事なので、カードだけを見ても分かるようにするため
- 指標：カードの下の区切り線の下に、「関連度」「重要度」「反響」を、どれも名前と5つの目盛りの同じ形で並べる。名前のない記号だけで値を出さない。AI を使えなかった日は、反響だけを出す。目盛りは muted で塗り、5のときだけ accent にする
  - 理由：何の指標かが分からないと読めないため。同じ5段階なので、同じ形にして見比べやすくする
  - 理由：関連する記事は4〜5になりやすく、4から赤にすると画面中が赤くなり、ほかの赤が埋もれるため
- 要約：一覧では4行までにして、末尾を「…」で切る。4行に収まらないときだけ、下に「続きを表示」（下向きの矢印）を出し、押すと全文を開く（「折りたたむ」で戻す）
  - 理由：要約が150〜300字あり、全文を出すとスマホでカード1枚がほぼ1画面になり、毎朝さっと把握できないため
- 記事のリンク：見出しと「記事を開く」で元記事を開く。Ask HN は元記事がないので「HN で開く」にする。スコアやコメントの数と、HN のコメントのページへのリンクは出さない
- 印のボタン（保存・既読・興味なし）：ログインしているときだけ、カードの右上にアイコンで並べる。ログインしていないときは出さない（押せないボタンも見せない）
  - 興味なしにした記事は、点線の枠の1行に畳み、「元に戻す」を置く
  - 既読の記事は文字を muted にし、「既読」と出す
- メニュー（カレンダー、アカウント）：押したボタンの下に surface の面で出し、外を押すと閉じる
- 一覧から1つを選ぶもの（キーワードを追加するときのカテゴリ）：ブラウザ標準のプルダウン（select）は使わず、入力欄と同じ高さ・枠のボタンに、選んでいる名前・件数・下向きの矢印を出す。押すと、すぐ下に surface の面でリストを開き（矢印は上向き、ボタンの枠は ink）、各行に名前と件数を出す。選んでいる行は、左に link のチェックと太字、地の色の面にする。リストは全件をスクロールなしで見せ、最後の行の下に区切り線と「カテゴリを作成」を置く（10個に達したら出さない）
  - 理由：標準のプルダウンは OS ごとに見た目が変わり、紙と墨の色に合わないため。件数を見ながら選べるようにする
- 過去の日を見ているとき：ヘッダーのすぐ下に notice の細い帯を出し、「〇/〇（〇）の一覧を表示中」と「最新へ ›」を置く。今日の一覧では出さない
  - 理由：日付の文字以外が今日と同じだと、過去の一覧を見ていると気づきにくいため。スマホのヘッダーには置く幅がない
- キーワード設定：上の追加フォームのほかに、各カテゴリの見出しに「＋」を置き、押すとそのカテゴリのいちばん上に、入力欄・優先度・「追加」の1行を開く（＋は×になり、押すと閉じる）。PC ではカテゴリを2列に並べる
  - 理由：キーワードが数十個になると縦に長くなり、下のカテゴリに足すたびに上のフォームまで戻らずに済むようにするため
- 3つから1つを選ぶもの（優先度の高・中・低）：つながった小さなボタンにし、選んでいるものを ink で塗る
- 取り消せない操作（カテゴリの削除）：確認のダイアログを出し、ボタンは「キャンセル」と「削除」にする。スマホでは画面の下から出し、PC では中央に出す
- 取り消せる操作（キーワードの削除）：すぐに削除し、画面の下の通知に「元に戻す」を置く
- 一時的な失敗やお知らせ（同期に失敗した、自分以外のアカウントでログインしようとした、キーワードを削除した）：画面の下に ink の地の通知を出す
- 入力のエラー：入力欄の枠を accent にし、すぐ下に accent の文字で理由を出す

## 状態の見せ方

- 0件・まだ使えない：一覧の場所に、太字の1行、補足、次にできる操作のボタンを出す。アイコンは出さない（読み込めなかったときだけ、エラーのアイコンを出す）
- 読み込み中：記事のカードの形をした灰色の枠（スケルトン）を出す
- 読み込めなかった：0件と同じ形で、「再読み込み」ボタンを出す
- 一部の情報が欠ける日（AI を使えなかった日など）：一覧の上に notice のお知らせを出し、欠けている理由と、今の並び順を書く

## 文言

- 要約は、である調。画面の案内は、ですます調で短くする
- ボタン・見出し・ラベルは、アプリで一般的な短い語にする。和語の動詞（「足す」「消す」「作る」「やめる」）ではなく、漢語やカタカナ語の名詞（「追加」「削除」「作成」「キャンセル」「再読み込み」「再試行」「保存済み」「キーワード設定」）を使う
  - 理由：くだけた和語の動詞が並ぶと、幼く見えるため。よく見る語のほうが、読まずに押せる
- 状態は「〜済み」「〜に失敗しました」の形で短く言う（「登録済みです」「同期に失敗しました」）。長い説明は付けず、次にできることだけを添える
