# 概要

## 目的

毎朝、自分が登録したキーワードに関連するニュースを、日本語で手早く把握する。記事は Hacker News から集め、今後ほかのソース（RSS など）も足していく。
キーワードに関連する記事だけを読んでいると視野が狭くなるので（エコーチェンバー、フィルターバブル）、キーワードに関係なく反響の大きかった記事も少し混ぜる。

## 使う人

自分ひとり。主にスマホで、PC でも読む。記事の一覧は公開のページとして誰でも読めるようにする。キーワードの設定と、保存・既読・興味なしの印は、自分の Google アカウントでログインしたときだけ使える（スマホと PC でそろう）。ほかの人には、印のボタンも、保存した記事やキーワードの設定の入口も見せない。

## 主な機能

<!-- 画面のプロトタイプで流れを決めたあと（立ち上げの S3）、それぞれ GitHub の Issue にする -->

- 毎日 JST 7:00 に、ソースの注目記事を自動で取得し、その日の一覧に載せる記事（30件ほど）を選ぶ
  - 8割：登録したキーワードに関連する記事。AI が、キーワードとの関連度（1〜5）、一致したキーワード、カテゴリを付ける
  - 2割：どのキーワードにも一致しなかったが、反響の大きかった記事（キーワード外）
  - どちらにも、AI が日本語のタイトル・要約（150〜300字）・重要度（1〜5）を付ける
- その日の一覧を読む。キーワードに関連する記事を関連度の順に並べ、そのあとにキーワード外の記事を反響の順に並べる。記事ごとに、ソース、カテゴリ、一致したキーワード、関連度、重要度、反響が分かる
- 日付を切り替えて、過去（直近90日）の一覧を読む
- カテゴリで絞り込む。キーワード外の記事だけを見ることもできる
- AI が使えなかった日も、英語タイトルで一覧を読める（キーワードでの仕分けはせず、反響の順に並べる）
- キーワードを設定する：カテゴリ（キーワードのまとまり。10個まで）を作り、その中にキーワードを数十個登録し、キーワードごとに優先度（高・中・低）を決める。変更は次の朝の取得から使われる
- 自分の Google アカウントでログインし、記事に保存・既読・興味なしの印を付け、保存した記事を日付をまたいで一覧で読む
- 画面の明暗を切り替える（最初は OS の設定に従う）

## やらないこと

- 記事本文の転載（要約と元記事へのリンクだけ）
- AI に記事を取得させること（取得はコードで行う）
- 複数のユーザー
- 記事を DB に置くこと（記事は JSON のファイルに置く。DB に置くのは、キーワードの設定と、保存・既読・興味なしの印だけ）
- 自分以外のアカウントでのログイン、ユーザー登録（ログインできるのは、決めておいた自分の Google アカウントだけ）
- 1日に何回も更新すること。キーワードを変えたときに、その日の一覧を選び直すこと
- スコアやコメントの数を画面に出すこと（反響の5段階だけを出す）

## 技術

| 用途 | 使うもの | 選んだ理由 |
| --- | --- | --- |
| 言語・フレームワーク | TypeScript、Vite + React | 取得・要約のスクリプトと表示ページで記事の型を共有でき、静的なファイルを出すだけの作りに合う |
| データベース | Firebase（Authentication、Firestore） | 静的なページから Google ログインと読み書きができ、無料のまま使わない日が続いても止まらない。記事は DB に置かず JSON のファイルに置く |
| 要約の AI | Gemini の Flash-Lite 系（無料枠） | 費用が0円。記事は公開のものなので、送った内容が改善に使われても問題が小さい |
| テスト | Vitest、Playwright | Vitest は Vite の設定をそのまま使える。ブラウザでの操作と画面の画像は Playwright で確かめる |
| 整形・Lint | Biome | 1つの道具で速く、編集のたびにかけても待たない |
| 定期実行・CI | GitHub Actions | リポジトリと同じ場所で、cron・手動実行・PR のチェックができる |
| デプロイ先 | GitHub Pages | 静的なファイルを無料で公開できる |

## 用語

<!-- 同じものを別の言葉で呼ばないために書く -->

| 用語 | 意味 |
| --- | --- |
| ソース | 記事を取得する元（今は Hacker News だけ） |
| キーワード | 読みたい記事を選ぶために、自分で登録する言葉。数十個を想定する |
| カテゴリ | 自分で作る、キーワードのまとまり（例：「AI」に LLM、Claude などを入れる）。10個まで、名前は6文字まで。記事は、一致したキーワードのカテゴリに仕分ける（複数のカテゴリのキーワードに一致したら、優先度がいちばん高いキーワードのカテゴリに入れる）。一覧の絞り込みに使う。今の想定は、AI、Web開発、言語・ツール、開発手法、データ・DB、クラウド、インフラ、セキュリティ、機械・電機、IT業界。政治・経済やデバイスなどはカテゴリを作らず、反響が大きければキーワード外に入る |
| 優先度 | キーワードごとに決める 高・中・低。高いキーワードに関連する記事ほど、関連度を高く見る |
| 関連度 | AI が付ける 1〜5 の値。記事が、登録したキーワードにどれだけ関連するか |
| 重要度 | AI が付ける 1〜5 の値。キーワードに関係なく、ニュースとしてどれだけ重要か |
| 反響 | そのソースの直近30日の記事と比べて、スコアやコメントの数がどれだけ多いかを、偏差値のように5段階に分けたもの。コードで計算する |
| キーワード外 | どのキーワードにも一致しなかったが、反響の大きかった記事。一覧の2割。視野が狭くならないように混ぜる。「その他」ではなく、キーワードに一致せず反響の小さい記事は一覧に載せない |
| 投稿の種類 | HN の Show HN（作ったものを見せる投稿）と Ask HN（質問の投稿）。タイトルの頭からコードで判定する |
| 保存 | あとで読むために記事に付ける印。付け外しできる |
| 既読 | 読んだ記事に付く印。元記事を開くと付き、手でも付け外しできる |
| 興味なし | 一覧で畳んでおく記事に付ける印。元に戻せる |
| 印 | 保存・既読・興味なしをまとめた呼び方 |
| ログイン | 自分の Google アカウントで入ること。ログインしているときだけ、印とキーワードの設定を使える |
