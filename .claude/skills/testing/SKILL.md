# テストの基準

テストは、**間違えたときに、触っても気づきにくいところ** に書く。受け入れ条件1つにテスト1つ、とはしない。

## 確かめ方は3種類

| 確かめ方 | 使うもの |
| --- | --- |
| テスト | 下の「テストを書くもの」 |
| 触って確かめる | 画面を見ればわかるもの（いつも出ている文言、色、配置など）。見た目は、本番の画面の画像でも確かめられる |
| コードを見て確かめる | 値を1か所に書くだけで、触っても確かめにくいもの（ログイン状態の期限など）。PR のレビューで見る |

## テストを書くもの

- 条件によって結果が変わるところ（入力チェック、エラーの出し分け、ログインしているかどうかでの移動）。条件で出し分ける文言もここに入る
- 計算
- 保存と読み出し（データベースに入る・入らない）
- 境界の値（境界の両側を1つずつ）

## テストを書かないもの

- 値を1か所に書くだけのもの（いつも出ている文言、設定値、ページの情報、テーブルの列）。テストがコードの写しになるだけのため
- ほかのテストの裏返し（「〇〇になる」を確かめたうえでの「初期値ではない」など）
- ライブラリそのものの動き、型チェックで見つかる間違い
- すでに別の層で確かめた決まり。1つの決まりは、いちばん中心の層で1回だけ確かめる。画面のテストでは、その結果がどの文言で出るかだけを確かめる

## 数の目安

- 同じ扱いになる入力は、代表を1つだけ試す
- 1つの分かれ道には、行く側と行かない側を1つずつ

## 画面の画像を比べるテスト

受け入れ条件とは別に、本番の画面を撮って `docs/specs/screens/` の画像と比べるテストを、いつも実行する（screenshots スキル）。
画面を変えるつもりのない変更で、見た目が変わったことに気づくため。
