# 画面のプロトタイプの決まり

見た目や操作の手触りは、言葉だけでは人間とAIの理解がずれやすい。そこで、本番を作る前に、触れる形で合意する。
プロトタイプは **合意するための道具で、本番のコードの手本にはしない**。作るかどうかは、`/dev-spec` が決める。

## 作るもの・作らないもの

| 作る | 作らない（仕様ファイルの文章だけで決める） |
| --- | --- |
| レイアウト、色、余白、文字 | データの保存、API、認証 |
| 状態ごとの表示（0件、大量、読み込み中、エラー、権限なし） | 入力チェックの中身。エラーの **見た目** だけを、決まった状態として作る |
| 画面のつながり（どのボタンでどこへ行くか） | 計算、並べ替え、検索の中身 |
| 操作の手触り（開閉、確認ダイアログ、エラーの出方） | 本物のデータ。表示用の決まったデータをページに書く |

## 技術

- HTML＋Tailwind CSS。開閉などの動きが要るところだけ Alpine.js を使う
- ビルドは Tailwind の CLI だけ。ビルド結果の CSS もコミットし、ファイルをブラウザで開けば見られるようにする（サーバーやバックエンドは作らない）
- 色・余白・文字は、トークン（`tokens.css`）にあるものだけを使う
- 状態は URL の `?state=empty` などで切り替える。`index.html` に、画面と状態の一覧を置く
- スクリーンショットは Playwright で、画面と状態の組み合わせごとに撮る
- 本番がどの技術でも、プロトタイプは HTML のままにする。部品の分け方や状態の持ち方がないので、本番がまねる材料にならないため

## 置き場所と、本番に見せない仕組み

本番を作るAIには、プロトタイプのソースを見せない。見せるのは仕様ファイル、スクリーンショット、`docs/ui.md`、トークンだけ。見えたものには引っ張られるので、ルールで禁じるより、見えない場所に置く。

- プロトタイプは、**このリポジトリの外の別フォルダ** に、別の Git リポジトリとして置く。場所は人間が決める
- `/dev-proto` の会話でだけ、`/add-dir <プロトタイプのフォルダ>` で作業ディレクトリに加える。その会話だけにして、設定には保存しない
- `/dev-proto` が終わったら会話を区切る。同じ会話のまま本番を作ると、AIが直前に書いたプロトタイプの作りをまねるため
- トークンは、本番のトークンファイルからプロトタイプへ、一方向にだけコピーする（立ち上げだけは、プロトタイプで決めたものを `docs/tokens.css` に仮置きし、本番の置き場所へ移す）

## 合意したものの残し方

| もの | 場所 |
| --- | --- |
| 立ち上げで合意した画面のスクリーンショット | `docs/agreed-screens/<画面>-<状態>.png`。その機能の `/dev-spec` が仕様を書き起こす元にする。本番の画像（`docs/specs/screens/`）に引き継がれたら消す |
| 変更で合意した画面のスクリーンショット | `docs/changes/<年-月-日>-<何をするか>/<画面>-<状態>.png`。仕様PRで取り込む |
| 決まった動き・文言 | 仕様ファイル（機能を仕上げたら `docs/specs/`） |
| 見た目の決まり | 仕様ファイルの「画面」（機能を仕上げたら `docs/ui.md`） |

- 決めたことは必ず上のどこかに書く。プロトタイプにしかない決めごとを作らない
- プロトタイプは消さずに残し、次の変更でも使い続ける
- `docs/agreed-screens/` は「今の画面」（`docs/specs/screens/`）とは別にする。まだ本番にない画面を、比べるテストの基準と混ぜないため
- プロトタイプは画面が変わるときだけ直すので、本番より古くなることがある。変更のときは、最初に `docs/specs/screens/` と見比べ、プロトタイプを今の本番に合わせてから変える
