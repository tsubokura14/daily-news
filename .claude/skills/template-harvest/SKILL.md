argument-hint: <使う側のリポジトリの owner/repo>

使う側のリポジトリ `<owner/repo>`（コマンドのあとに書かれたもの）で直された、テンプレートのファイルの変更を集める。**入れるかどうかを決めるのは人間。** テンプレートはまだ直さない（直すのは、Issue にしてから）。

1. このリポジトリに `.template-version` があれば、使う側のリポジトリなので止まって伝える（このスキルはテンプレートのリポジトリで使う）
2. main を最新にする。`docs/template-files.md` を読み、対象のパスを決める
   - 「テンプレートのもの」「両方が書くもの」と、`CLAUDE.project.md`（「うまくいかなかったことから追加したルール」に足された行だけを見る）
   - 「テンプレートだけで使うもの」は `:(exclude)<パス>` で外す
3. `git fetch https://github.com/<owner/repo>.git main` を実行し、`git rev-parse FETCH_HEAD` を `<head>` として控える
   - `git show <head>:.template-version` がなければ、止まって、使う側で `bash scripts/link-template.sh` を実行するよう伝える
4. 見る範囲を決める
   - `docs/template-harvest.md` に <owner/repo> の行があれば、「最後に見たコミット」`..<head>`
   - なければ、`git rev-list --max-parents=0 <head>` の最初のコミット`..<head>`（最初のコミットはテンプレートの写しなので見ない）
5. `git log --format='%H %s' <範囲> -- <対象のパス>` で、対象のパスを変えたコミットを一覧にする
   - `.template-version` を変えたコミットは外す。テンプレートの新しい版を取り込んだもので、使う側で直したものではないため
   - 1件もなければ、6〜7 を飛ばす
6. コミットごとに、`git show <コミット> -- <対象のパス>` で差分を見て、コミットメッセージ（PR の本文。直した理由）と合わせて、次の案を出す
   - テンプレートに入れる：ほかのプロジェクトでも起きる不備。テンプレートで何を直すかを、そのプロジェクトの言葉ではなく一般的な言葉で書く。使う側の直し方がそのプロジェクトに寄っていれば、テンプレートでの直し方を別に考える
   - そのプロジェクトだけの話：技術やそのプロジェクトの事情で書き足したもの
   - 捨てる：直し方が誤り、またはテンプレートですでに直っている（今の main と比べる）
   - 同じ不備を直した複数のコミットは、1件にまとめる
7. 人間に案を見せて決めてもらう。「テンプレートに入れる」と決まったものごとに、Issue の下書き（タイトル・本文）を見せ、承認されたら `gh issue create --body-file` で作る
   - 本文には、何が起きたか・テンプレートで何を直すかを書く。使う側のプロジェクトの名前・コード・データ・仕様の中身・テンプレートにないファイルのパスは書かない（このリポジトリから、ほかのプロジェクトにも写るため）。どのリポジトリから来たかは、最後に `<owner/repo> のコミット <短いハッシュ>` とだけ書く
8. main から `harvest-<repo の名前>` ブランチを作り、`docs/template-harvest.md` の <owner/repo> の行を、「最後に見たコミット」を `<head>`、「見た日」を今日にして書き換える（なければ足す）。コミットして PR を出す
   - タイトル：`<owner/repo> から集めたものを記録`
   - 本文：`.github/pull_request_template.md` に沿う。作った Issue の番号を「やったこと」に書く
9. 作った Issue と PR の URL を伝えて終わる

**マージはしない。**
