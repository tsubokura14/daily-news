---
name: dev-impl
description: 機能のタスクを1つ、テストを先に書いて実装し、タスクPRを出す。最後のタスクでは機能を仕上げる
argument-hint: <docs/changes/の仕様ファイル> <タスク名>
disable-model-invocation: true
---

次のタスクを1つ実装する。対象は、コマンドのあとに書かれた仕様ファイルとタスク名。

1. 仕様ファイルと、関係する `docs/specs/` を読む。対象のタスクと、それに関係する受け入れ条件・確かめ方を確認する
   - 画面のタスクなら、`docs/ui.md` と、タスクに書かれたスクリーンショット（仕様ファイルと同じ名前のフォルダ）も見る
2. main を最新にする。main の仕様ファイルで、次のどちらかに当たれば、伝えて止まる（読んだ仕様ファイルが古かったら、読み直す）
   - 仕様ファイルがない：仕様PRがまだ取り込まれていない
   - このタスクより前のタスクに、チェックの付いていないものがある：前のタスクPRがまだ取り込まれていない。順番に関係のないタスクだと人間が決めたら進めてよい
   - どちらにも当たらなければ、`<Issue番号>-<タスクの英語の短い名前>` ブランチを作る
   - このタスクのほかに、チェックの付いていないタスクがなければ、**最後のタスク**。手順7のあとに [finish.md](finish.md) に沿って機能を仕上げる
3. 確かめ方が「テスト」の受け入れ条件について、**テストを先に書き、実行して失敗することを確かめる**（実行はサブエージェント `test-runner` に、書いたテストのファイルを渡して頼む）。コミットする
   - testing スキルに従う
4. テストが通るように実装する。テストが通ったらコミットする
   - 理由と前提は、設計で決めた場所に書く（code-notes スキル）
   - AGENTS.md の「止まって聞くとき」に当たったら、推測で進めずに止まる。人間が決めたら、**先に仕様ファイルを直し**（同じブランチでよい）、それから再開する
5. 画面のタスクなら、**タスクに書かれた画面だけ** を本番から撮り直す（screenshots スキル）
   - その画面について、仕様ファイルの「画面」にある状態のうち、まだ撮っていないものを、撮る対象に足す
   - 撮り直した `docs/specs/screens/` の画像はコミットする
6. サブエージェント `test-runner` に「全部」を渡し、テスト・Lint・型チェック・画像を比べるテストがすべて通ることを確かめる。失敗したら直して、もう一度頼む
7. 仕様ファイルのタスクにチェックを付けてコミットする。最後のタスクなら、ここで [finish.md](finish.md) の「PR を出す前」を行う
8. サブエージェント `pr-check` に、仕様ファイルのパスとタスク名を渡し、差分を照らし合わせてもらう
   - ずれを直してコミットし、手順6からやり直す。直さないものは、理由を PR の「レビューで見てほしいところ」に書く
   - 「確かめてほしいこと」は、PR の「レビューで見てほしいところ」に書く
9. PR を出す
   - タイトル：何をしたかの日本語1文
   - 本文：`.github/pull_request_template.md` に沿い、`Refs #Issue番号`（最後のタスクは `Closes #Issue番号`）。チェックは実際の状態で埋める
   - 画面を撮り直したなら、撮り直した画像の一覧を、タスクに書かれた画面と並べて「やったこと」に書く
10. CI の結果を `gh pr checks --watch --fail-fast` で、終わるまで待って確かめる（PR を出した直後は、まだ動いているため）。失敗していたら直してから次へ進む
    - `no checks reported` と出たら（exit 1 で終わる）、失敗として扱わない。`.github/workflows/` がなければ、CI はまだないので確かめずに進み、最後に「CI がまだないので確かめていない」と伝える。あれば、チェックがまだ登録されていないので、少し待ってからもう一度確かめる
11. PR の URL と、人間がレビューで特に見るべきところを伝える。確かめ方が「触って確かめる」のものがあれば操作の手順を、「コードを見て確かめる」のものがあれば見る場所（ファイルと行）も伝える。画面を撮り直したなら、変わった画像の一覧も伝える。最後のタスクなら、[finish.md](finish.md) の「PR を出したあと」も伝える。そうでなければ、次に打つ1行 `/dev-impl <仕様ファイルのパス> <次のタスク>` を伝える

**マージはしない。**
